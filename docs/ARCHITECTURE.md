# OPUS — Architecture & codebase map

The efficiency reference: what exists and where. Check here before grepping. Keep updated when adding a table, field, util, hook, route, store, or localStorage key.

## Stack
Vite 5 · React 18 · Tailwind v4 (CSS-first, no tailwind.config.js) · Dexie.js (IndexedDB) · Zustand · React Router v6 · **visx** (charts) · react-body-highlighter · lucide-react · vite-plugin-pwa. Vitest (node env) for unit tests, Biome for linting, Playwright for E2E. Deploy: GitHub Pages via `.github/workflows/deploy.yml` — a `test` job (**lint → test → build**) and a separate `e2e` job both gate build-and-deploy; base path `/opus/`.

**Repo shape:** web-only. `src/` · `docs/` · `public/` · `tests/e2e/` · `scripts/` + root config. There is no native app, no `packages/`, and no monorepo tooling — `src/utils/*` is the single source of truth for pure logic.

## Stores (`src/store/`)
- **workoutStore** — `activeWorkout` (+localStorage write-through/hydrate, `resumed`/`dismissResumed`), start/startFromTemplate/repeatWorkout, addExercise/removeExercise/**moveExercise**, logSet/removeSet/setSetNote/toggleWarmup, **toggleSuperset**, setEnergy/Name/Notes, **completeWorkout** (writes DB, PR detection, XP/streak, achievements; returns {workoutId,prCount,**prs**,xpEarned,leveledUp,newLevel,newTitle,newAchievements,dungeon}; `prs` carries name/type/value/prev per record, since a bare count can only say "1 new record"), discardWorkout.
- **userStore** — profile init/update, `addXP` (recomputes level/title).
- **uiStore** — toasts + promise-based `confirm`/`prompt`; `showToast(message,opts)`.

## Key components
- layout: AppLayout, BottomNav, PageWrapper, TopBar
- workout: WorkoutPage, ExerciseSection (link/superset + up/down), SetLogger, RestTimer, PlateCalculator, ExercisePicker, EndWorkoutModal, WorkoutCard
- rpg: CharacterCard (composes `charts/RadarChart` + the monthly overlay), XPBar, LevelBadge, TitleBadge, AchievementBadge, TrophyCase, QuestBoard
- progress: MuscleFrequency, Heatmap, RecoveryMap (prop-driven: `data/onSelect/legend/title/icon`; falls back to `useRecovery`; exports `MUSCLE_LABEL`), ActivityRings, WeeklyRecap, ActivityForm, BodyStatsForm, SleepForm, PRBadge
- share: ShareSheet (canvas preview + theme/accent pickers), ShareButton (`kind` + `data`). The cards themselves are **not components** — they are canvas renderers in `utils/shareCards.js`.
- logo: **OpusMark** — the OPUS monogram, an "O" drawn as a living ring of light on **canvas 2D** (not SVG, not a raster). Conic accent gradient + a rotating specular arc; `level` thickens it and adds a stud per level, `prestige` adds a crown. Animation gated on `effects` + reduced-motion (static frame otherwise). `LoadingScreen` composes it with a letter-by-letter wordmark.
- **App icons** are generated, not hand-made: `node scripts/make-icons.mjs` renders `public/icon-{192,512}.png` from the same monogram via headless Chromium, so the icon can't drift from the palette. Maskable-safe (mark inside the inner 60%, ground bleeds to the edge).
- **cinematic (`src/components/cinematic/`)** — the celebration layer. `CinematicHost` is mounted once in `AppLayout` (not by the page that produced the event — the old level-up screen was owned by `WorkoutPage`, the component about to unmount) and plays `cinematicStore`'s queue one item at a time. `Stage` is the shared shell: ground, enter/exit, particle burst, and the single place sound + haptics fire. `PRCinematic` / `LevelUpCinematic` / `DungeonCinematic` are full-screen; `AchievementCinematic` stays a bottom card stack, since several can land at once and a takeover per badge would bury the record that earned them. **There is no skip** — see the pattern below.
- **charts (`src/components/charts/`)** — the whole chart language, built on **visx** (`@visx/scale`, `@visx/shape`, `@visx/curve`). `ChartFrame` owns everything shared by the cartesian charts (measuring, scales, grid, axes, scrub, readout) and takes the plot itself as a render prop, so `TrendChart` (line) and `VolumeChart` (bar) cannot drift apart on padding, tick density or interaction. `RadarChart` is deliberately *not* visx — five points on a circle is geometry, and `utils/chartMath.js` already has it tested and shared with the vertex dots and label placement. `useMeasure` (callback ref + ResizeObserver) and `useScrub` (drag-to-inspect) sit alongside.
- **streak (`src/components/streak/`)** — `StreakRescueHost` is mounted once in `AppLayout` and decides whether a lapse is still buyable; `StreakRescueModal` is the offer. App-wide rather than on Home because a lapse should be caught wherever you come back to, and because Home was the only place a rest token could ever be spent, which is why nobody found them.
- fx: Particles, CountUp · logo: OpusMark (evolves by level/prestige), LoadingScreen · ui: Modal, UiHost, ColorPicker · coach: CoachMark · tour: Tour · settings: EquipmentModal, ResetDataModal

## Reusable patterns
- **Share**: build a `data` object → `<ShareButton kind="workout|profile|recap|challenge|wrapped" data={...} />`. Cards are drawn to a 1080×1080 canvas: pure layout/format maths in `utils/cardLayout.js` (tested), drawing primitives in `utils/canvasKit.js`, the five compositions in `utils/shareCards.js`, and render/share in `utils/share.js`. The ShareSheet preview canvas **is** the exported image (CSS-scaled), so preview always equals output. `ensureFonts()` must run before drawing — canvas silently substitutes a fallback for any face that has not loaded.
- **Sound/haptics/fx**: `playChime(kind)`, `useHaptics()(kind)`, `<Particles/>`, `<CountUp/>` — all gated by effects/sound.
- **Week math**: `weekKeyOf/weekStartMs` (quests.js, Monday-aligned). **Month/year**: wrapped.js + snapshots `monthKeyOf`.
- **Delete-revert**: deleteWorkout → recomputePRs + reconcileAchievements + reconcileQuests + recomputeProfile.
- **Persisted prefs**: settingsStore `load()`/`persist()` localStorage pattern.
- **Motion (`src/motion/`)** — `spec.js` holds the whole vocabulary (`SPRING.sheet/layout/pop`, `TWEEN.micro/standard/enter`, page/list/sheet variants); durations mirror the CSS tokens so a CSS fade and a Motion move arrive in one beat. `index.jsx` exports `m`, `AnimatePresence`, the spec, `useMotionEnabled()`, and `MotionProvider` (wraps the router in `main.jsx`). **Always import `m`, never `motion`** — `LazyMotion` runs in `strict` mode so the full library can't leak into the main chunk, and the `domMax` feature set is a lazily-fetched chunk (`motion/features.js`). Gating is central: `reducedMotion="user"` plus a zero-duration transition when `effects` is off, so components don't each re-implement the rule.
- **Lists that get long**: History groups by month with per-month totals, Exercises groups by initial letter (`<ExerciseList grouped />` — off by default, since the pickers reusing it show short filtered sets). A sticky group heading must be **fully opaque**, not `--glass-chrome`: at 94% the row scrolling behind it stays legible through it, which reads as a rendering fault.
- **Celebrations**: build nothing at the call site — hand `completeWorkout`'s result to `useCinematicStore.getState().celebrate(result)` and it returns how many cinematics were queued (0 for an ordinary session, which is the common case). Ordering, collapsing and pacing are pure logic in `utils/cinematics.js`. Three rules worth knowing: **many records collapse into one cinematic** (three sets of three lifts can produce nine at once) with the rest counted; **the queue speeds up as it grows**, because with no skip button the total length is what has to stay honest; and the pacing `scale` travels with each item so the entry delays shorten in step — otherwise a sped-up cinematic introduces its last line as it leaves. **The host's timer is load-bearing**: it is the only thing that ends a cinematic, it sits outside the error boundary so a cinematic that fails to render still advances, and an E2E test asserts the queue always drains. With `effects` off the whole thing degrades to toasts via `summarize()` — the celebration is optional, being told you levelled up is not.
- **Charts**: `<TrendChart data={[{label, value}]} unit empty />` for a trend, `<VolumeChart data={[{label, volume}]} unit />` for magnitude, `<RadarChart data={[{axis, value, valuePrev}]} />` for the character sheet. Colour comes from CSS custom properties applied directly to SVG attributes (`stroke="var(--color-gold)"`) — no JS reads computed styles, so a theme flip recolours every chart with no re-render. Inspection is **drag-to-scrub, not hover tooltips**: a hover tooltip is a desktop idea, and on a phone it degrades into poking at a series point by point. Each crossed point ticks the haptic motor once (touch only). Gradient `id`s come from `useId()` — several charts share a page and duplicate ids silently cross-wire their fills.
- **Route transitions** live in `AppLayout` — a `m.div` keyed on pathname, **enter-only, no `AnimatePresence` exit**. An exit keeps the outgoing page mounted while the new one arrives, putting two copies of the same landmark in the DOM: bad for assistive tech and a source of ambiguous-locator flake. Pages no longer carry `anim-fade-slide-up` (overlays and toasts still do).
- **Design system — AURORA** (adopted 2026-08-05). `styles/tokens.css` is the entire visual identity. Token names are semantic, not literal: `chalk`=canvas, `ivory`=card surface (translucent), `stone`=**deep panel, dark in BOTH themes** (it pairs with `text-inverse` everywhere — flipping it puts light text on light ground), `obsidian`=ink-on-accent, `gold`=accent (violet `#8b7dff`), `ember`=blush warn, `sage`=teal good. Accent + its ink are constant across themes so every `background:gold/color:obsidian` pair keeps contrast. Material tokens: `--aurora` (the three-light backdrop, swappable for a shader later), `--grad-accent`, `--glass-line`, `--glass-blur`, `--glow-accent`, `--elev-1..3`.
- **Glass** is opt-in via `.glass` / `.glass-strong` in `index.css`, never global — `backdrop-filter` is the most expensive thing on a mid-range Android GPU. `.glass-strong` is for chrome content scrolls under (the nav). There's an `@supports not` solid fallback.
- **Theme cross-fade** is scoped to `html[data-theme-anim]`, stamped by `applyTheme` for 400ms. As a permanent global `*` rule it was a paint cost on every element of every list.
- **Styling**: Tailwind v4 is configured in `src/index.css` via `@theme inline`; there is no `tailwind.config.js` and no `content` array (v4 auto-detects). `styles/tokens.css` stays the single source of colour truth and the theme block only *points* at it, so every Tailwind colour utility is theme-aware. Semantic utility names: `surface`/`surface-alt`/`panel`/`canvas`/`ink`/`ink-soft`/`ink-inverse`/`accent`/`warn`/`good`/`muted`.
- **Token naming — do not reuse Tailwind namespaces.** Project tokens are `--opus-radius-*` and `--opus-ease-out` precisely because `--radius-*` and `--ease-*` are Tailwind v4 theme namespaces. `tokens.css` is unlayered so it silently *overrides* anything Tailwind puts in `@layer theme` — a plain `--radius-2xl` in tokens.css re-sizes every `rounded-2xl` in the app. Name new tokens `--opus-*` unless you intend that.
- **Transforms**: v4 compiles `translate-*`/`scale-*`/`rotate-*` to the standalone `translate`/`scale`/`rotate` properties, which **compose with** an inline `transform` instead of losing to it. Never put a transform utility and an inline `transform` on the same element.
