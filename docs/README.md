# OPUS docs

Project home for plans, references, and memory. Start with the file that fits your need:

| File | What it's for |
|------|---------------|
| [ARCHITECTURE.md](./ARCHITECTURE.md) | Codebase map — routes, DB tables, localStorage keys, every util/hook/store/component, reusable patterns. **Check before grepping.** |
| [GUIDELINES.md](./GUIDELINES.md) | Engineering rules, UX standards, data-integrity, testing, the "wow in every feature" rule, workflow. |
| [RELEASES.md](./RELEASES.md) | What shipped in v1.0.0 / v2.0.0 / v3.0.0. |
| [STATE.md](./STATE.md) | Live status + detailed reverse-chronological build log. |
| [PRD.md](./PRD.md) | Original product requirements (MVP Sprints 1–10). |
| [ROADMAP_V2.md](./ROADMAP_V2.md) | Sprints 11–20 plan. |
| [ROADMAP_V3.md](./ROADMAP_V3.md) | v3 plan (resume workout, reminders, reorder, equipment, export, Wrapped, living scene). |

The repo-root [`CLAUDE.md`](../CLAUDE.md) is the auto-loaded entry point (preferences + workflow + this map). Keep `STATE.md` updated each sprint and `ARCHITECTURE.md` updated when the structure changes.
